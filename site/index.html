Isolation is the whole trick.

Parallel agents are easy. Parallel agents that do not corrupt each other's work is the part that needs a mechanism, and jj workspaces are it.

A workspace per agent

Each agent gets its own jj workspace: a private copy of the repo, gitignored, beside your checkout and never in it. It cannot see, stash, or overwrite anyone else's edits.

All of them at once

Claude Code, Codex and opencode run side by side, on the same repository, without a single branch checkout between them.

A real diff, per row

Nothing lands that you have not been shown. m on work you have not read opens its live jj diff instead of merging; a second m lands it.

One road to main

On a repo with a GitHub remote, that second m opens a draft pull request. Without one, it merges locally and u undoes it. Never both, so nothing lands twice.

Three things you can type.

The task box takes plain language. What you type decides where the work lands, and that is the only decision you have to make.

you type what happens where it works
fix the login redirect One isolated agent Plain text is the default. It never touches your checkout and merges with m. its own workspace
/plan ship billing v2 An orchestrator Breaks the goal into a task graph you can edit, then runs and merges the nodes as their dependencies land. Run it again for a second goal and you get a second orchestrator beside the first, each with its own graph and its own pane. one workspace per node
/main tag the release An agent in your checkout For the jobs that are actually about your working tree. Nothing to merge, because it is already here. your real checkout

Three panes, three jumps.

Option-1, Option-2 and Option-3 always mean the same three places. The worker pane belongs to the agent, so dashboard keys from inside it take the Ctrl-W leader.

option-1

Agents

Every run on one sheet. Move with j/k, then review, merge, rename or delete.

option-2

Worker

The agent's own terminal, unmodified. Talk to Claude or Codex directly; their prompts stay native.

option-3

Task

Where work starts. Type a task, or steer a plan that is already running.

Set once. The next agent picks it up.

/model sets the backend, model and reasoning effort Rudder will use, and remembers it. A running agent keeps whatever it launched with.
